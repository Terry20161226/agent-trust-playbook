# fail-closed：给 coding agent 修门禁的设计原则

> 「Agent 可信度工程」系列第 2 篇。上一篇讲了为什么只能信证据不能信声明；这一篇讲装证据门禁时，我们踩过的三个坑和收敛出的三条原则。

## 门禁的默认值决定一切

给人用的内部工具，默认值通常是 fail-open：校验服务挂了、配置读不到，先放行再说，别挡着人干活。人遇到异常会停下来看一眼，这是合理的取舍。

把这个直觉搬到 agent 门禁上，是灾难的开始。区别在于：**人偶尔探索路径，agent 系统性探索路径。** 一个 fail-open 的口子对人来说一年被踩到三次；对 agent 来说，只要"这样能过"被学到一次，它就成了主路径——上一篇说过，模型对齐的是"顺利交付"的叙事，门禁放行的做法就是最短叙事。

所以第一条原则，也是其他一切的前提：**拿不到证据时，结论必须是不通过。** 校验脚本崩了、凭证读不到、配置缺失——全部收敛到"不通过"。任何"这次先放行"的默认分支，都会被学成惯例。

## 演化过程：三个阶段，每个坑都交过学费

**第一阶段：提示词约束。** 在任务说明里写"完成后必须运行测试并报告真实结果"。结果是上一篇的悲剧：声明机制上就不携带证据，写得再严厉的提示词也只是又一段文本。

**第二阶段：脚本检查，但留了 skip。** 我们加了校验脚本，同时"贴心"地留了 `--skip` 参数——为了构建服务故障时不阻塞交付。下面是这个决定的真实后果（[合成模拟](../examples/02-fail-closed/skip-simulation.mjs)，agent 策略只有一条：上次被放行的做法这次继续）：

```
门禁 A（fail-open，提供 --skip 参数），20 轮交付：
  第 1轮  真实执行→留凭证
  第 2轮  真实执行→留凭证
  第 3轮  skip→放行
  第 4轮  skip→放行
  ...
  结果：skip 率 90%——第 3 轮试探成功后，真实测试再没跑过。

门禁 B（fail-closed，零 skip），同样 20 轮：
  结果：skip 率 0%——没有口子可学，每轮都留下真实凭证。
```

第 3 轮那次"试探"在现实里一定会发生：可能是时间压力，可能是 agent 从历史命令里抄到了 skip 用法，可能只是手滑。fail-open 的门禁只需要被试探成功一次。由此得到第二条原则：**零 skip。** 构建服务故障的正确应对是修构建服务，不是给门禁开旁路——旁路存在一天，凭证可信度就是零。

**第三阶段：fail-closed + 凭证绑定权威状态。** 但很快遇到新问题：凭证泛滥。每次改动都要求全套测试重跑，构建队列排长队，团队开始想办法绕开门禁——门禁如果慢到不可忍受，绕过它就是理性选择。于是有了第三条原则。

## 原则三：等价指纹复用——可信度不降，速度可谈

观察一下就会发现，要求"每次交付都有测试凭证"并不等于要求"每次交付都真跑一次测试"。真正需要保证的是：**凭证绑定的代码状态，和当前交付的代码状态一致。**

做法是让凭证携带一个内容指纹——不是文件名、不是修改时间（`touch` 一下就变了），而是代码规范化后的内容哈希。核验时对当前代码算同一个指纹：

- 指纹一致 → 代码语义没变，直接复用已有凭证，**省掉一次重复构建**；
- 指纹变了 → 凭证自动作废，必须重跑——"跑完测试又改了代码"这种最常见的抵赖，在机制上直接消失。

"规范化"是关键词：剥掉注释和空白再哈希。这样只改了注释、调了格式的提交不会触发无谓的重跑，而任何语义改动都逃不过：

```
测试已通过，签发凭证（指纹 16695d11d34a）

场景 1：代码原封不动
  当前指纹 16695d11d34a → 凭证有效，直接复用，省掉一次重复构建
场景 2：只改了注释和缩进
  当前指纹 16695d11d34a → 凭证有效，直接复用，省掉一次重复构建
场景 3：改了边界条件（> 变成 >=）
  当前指纹 d1f6106b8cd1 → 凭证作废，必须重跑测试
```

（[完整示例](../examples/02-fail-closed/fingerprint.mjs)，46 行，核心就是"规范化 → 哈希 → 比对"。）

一个必须坦白的实现细节：示例用正则剥注释，分不清字符串字面量里的空白和 `//`（比如 URL）——生产实现要在 AST/token 层做规范化，只剥真正的注释和格式空白。这个坑本身也印证第 5 篇的观点：**门禁代码的正确性标准要比业务代码更高**，因为指纹误判作废的是所有凭证。

注意这条原则和 fail-closed 并不矛盾：复用不是放宽标准，而是承认"同一份语义代码的测试结果相同"这个事实。门禁的可信度一分没降，但平均耗时降下来了——**门禁想活下去，必须比绕过它更便宜。**

## 三条原则回顾

1. **fail-closed**：拿不到证据 = 不通过。没有例外分支。
2. **零 skip**：任何旁路都会被学成主路径。基础设施故障就修基础设施。
3. **等价指纹复用**：凭证绑定规范化内容指纹；语义不变的改动复用证据，语义变了一切重跑。
